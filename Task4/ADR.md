### <a name="_b7urdng99y53"></a>**Название задачи:**

Расширение доступа к ставкам по депозитам для внутреннего и партнёрского кол-центров

### <a name="_hjk0fkfyohdk"></a>**Автор:** GigaCode

### <a name="_uanumrh8zrui"></a>**Дата:** 2025-04-06

### <a name="_3bfxc9a45514"></a>**Функциональные требования**

| **№** | **Действующие лица или системы**        | **Use Case**                           | **Описание**                                                                                       |
|:-----:|:----------------------------------------|:---------------------------------------|:---------------------------------------------------------------------------------------------------|
|   1   | Сотрудник кол-центра (внутренний)       | Просмотр актуальных ставок             | Оператор видит в своей системе актуальные ставки по депозитам, чтобы консультировать клиентов.     |
|   2   | Сотрудник партнёрского кол-центра       | Просмотр актуальных ставок             | Оператор получает ставки через внешнюю систему (файловый обмен), использует их для консультаций.   |
|   3   | Система управления ставками             | Экспорт ставок в файл                  | После обновления ставок система автоматически формирует файл (CSV/JSON) и выкладывает его на SFTP. |
|   4   | Внешняя система партнёрского кол-центра | Получение файла с актуальными ставками | Система регулярно забирает файл по SFTP и загружает в свою базу.                                   |
|   5   | Сотрудник бэк-офиса                     | Обновление ставок                      | Редактирует ставки в централизованной системе. Все изменения автоматически рассылаются.            |

### <a name="_u8xz25hbrgql"></a>**Нефункциональные требования**

| **№** | **Требование**                                                                                                        |
|:-----:|:----------------------------------------------------------------------------------------------------------------------|
|   1   | **Актуальность данных** — задержка между обновлением ставки и её появлением в кол-центре — не более 5 минут.          |
|   2   | **Надёжность доставки** — файл должен гарантированно доставляться на SFTP. При ошибке — повторная отправка.           |
|   3   | **Безопасность передачи** — SFTP с ключевой аутентификацией. Шифрование канала.                                       |
|   4   | **Совместимость формата** — файл должен быть в формате CSV или JSON, с чёткой документацией структуры.                |
|   5   | **Мониторинг** — логирование всех экспортированных файлов, уведомления при сбоях.                                     |
|   6   | **Интеграция без API** — партнёр не поддерживает REST, только файловый обмен. Решение должно быть устойчивым к этому. |
|   7   | **Минимальное влияние на АБС** — система управления ставками не должна зависеть от АБС.                               |
|   8   | **Поддержка версионности** — файл должен содержать метку времени и версию набора ставок.                              |

### <a name="_qmphm5d6rvi3"></a>**Решение**

#### 📌 Диаграмма 1: C4 Level 1 — Context Diagram

**Файл:** `diagrams/c4_context_rates_distribution.png`

На диаграмме показаны:

- **Система управления ставками** — центральный источник данных.
- **Внутренний кол-центр** — получает ставки через REST API.
- **Партнёрский кол-центр** — получает ставки через SFTP-файлы.
- **Сотрудник бэк-офиса** — редактирует ставки.
- **Внешняя система партнёра** — автоматически забирает файл.

Связи:

- Бэк-офис → Система управления ставками (HTTPS)
- Система управления ставками → Внутренний кол-центр (REST API, HTTPS)
- Система управления ставками → SFTP-сервер (SFTP)
- SFTP-сервер → Внешняя система партнёра (SFTP pull)

> ✅ Решение обеспечивает **один источник правды** (SoT) для ставок.
